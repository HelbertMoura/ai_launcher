# AI Launcher v23.1.0

The cost-governance release: Budget Guard learns per-project budgets — calendar-month quotas with their own alert thresholds, created from reconciled usage projects — sitting beside the existing rolling-window provider limits. The Costs surface gains a month projection card that estimates end-of-month spend from the recent burn rate, with an honest insufficient-data state when there is not enough history to project. Usage state is centralized in one shared, zod-validated store, projects are reconciled across workspace labels into canonical keys, and existing budgets migrate loss-lessly to the new v3 storage schema. Budgets still only alert — they never block; enforcement remains future work.

## Highlights

- **Per-project budgets**: a Providers | Projects tab switch (WAI-ARIA tablist with arrow-key navigation) lets each project carry a calendar-month quota with its own alert threshold, created from a dropdown of reconciled usage projects (canonical keys, deduplicated) with per-item removal.
- **Month-end projection**: the Costs hero gains a projection card — month-to-date spend, end-of-month projection from the 14-day daily-burn average, 7- and 14-day burn windows, and an estimated overflow date ("~Sep 28") when an active budget is projected to burst within its period. Fewer than 3 days with data renders an honest "insufficient data" state instead of a number, and a manual refresh button bypasses the backend cache.
- **Alerts, not blocks — on purpose**: budgets surface warnings (sidebar chip, inbox events, progress bars) but never interrupt work; hard enforcement is explicitly future work.
- **Canonical project reconciliation**: usage groups by a canonical project key (exact normalized path first, unambiguous basename fallback only) so the top-projects ranking shows one row per real project, with aggregated source labels in a tooltip and a per-project budget column (ok / warning / over).
- **Centralized usage state**: one shared, zod-validated usage store feeds the boot budget check, the status bar and every Costs surface — replacing four duplicated `read_usage_stats` invokes.
- **Loss-less budget migration**: storage schema moves v15 → v3 under the same `ai-launcher:v15:budget` key; the migration runs on the read path and on old backup imports (which previously never ran the entry's schema migration), and corrupt numerics fall back to safe defaults instead of dropping entries. Budgets from older versions migrate automatically with no data loss.
- **Accessibility & i18n**: every budget bar is an ARIA progressbar with `aria-valuenow/min/max` and accessible labels; the sidebar indicator reflects provider AND project budget health (worst percentage, dedicated `budget:project:<key>:<month>` inbox namespace); new strings shipped in English and pt-BR.

## Updater note

The fail-closed release pipeline introduced in v22.9.0 remains in force and is proven on this release: if `TAURI_SIGNING_PRIVATE_KEY` is not configured or the generated `.sig` is missing, the workflow aborts before publishing `latest.json`, and `scripts/audit-release.sh` re-checks that the published manifest carries a non-empty signature. An unsigned or empty-signature manifest cannot reach users, which protects the in-app updater from bricking itself with an update it would refuse to install.

## Notes

- All operations remain 100% local, offline-first, and private. No cloud sync, telemetry, or remote tracking.
- Windows remains the first-class platform; macOS and Linux builds ship the same core with platform-native secure storage and fail-closed gating for anything not yet available outside Windows.
- Project budgets are advisory in v23.1.0: they warn near and over the limit but never block launches; enforcement is deliberately deferred to a future release.
- Project reconciliation is conservative: ambiguous basenames stay ungrouped rather than risk merging unrelated projects.
