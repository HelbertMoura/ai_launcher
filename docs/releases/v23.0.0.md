# AI Launcher v23.0.0

The fleet-command release: Race Mode puts up to three agents on the same task in parallel, each in its own isolated git worktree, and closes the loop with a Diff & Review Cockpit whose adoption is always atomic — a race lands as a branch or as an apply report, never partially. Navigation is regrouped around the new model (collapsible Run / Observe / Connect / System groups, a fused Maintenance surface) and the whole app got a fluidity pass (tab-switch jank, progressive rechecks, batched history).

## Highlights

- **Race Mode**: up to 3 agents run the same prompt simultaneously, each in an isolated git worktree branched from the repository's base SHA, with live per-agent status columns, zod-validated contracts and a typed TS command layer.
- **Diff & Review Cockpit**: per-agent changed files and a unified colorized diff (pure CSS, 2 MB cap with truncation warning). Adoption is atomic: **Adopt (branch)** checks out the race branch; **Adopt (apply)** applies changes with a per-file conflict report and fails closed on renames — a race is never landed partially.
- **Auto-commit of uncommitted agent work**: `race_diff` and `race_adopt` snapshot an unclean worktree first (`git add -A` + a single commit on the race branch), guarded by a scope check that can never touch the user's own repository.
- **Race graveyard & crash recovery**: finished races persist newest-first with a 7-day retention window, restore and cleanup (race-scoped metadata sweep that resolves the relative `gitdir` paths written by git ≥ 2.46 and never reaps the user's own orphaned worktrees, including other drives). A boot-time orphan scan detects races whose app died mid-run; recovery verifies the persisted process identity before killing anything — unverified PIDs are surfaced in the report instead of being killed blindly.
- **Regrouped navigation**: sidebar with Home fixed, pinned surfaces and four collapsible groups (Run / Observe / Connect / System); Doctor + Prereqs + Updates fused into one Maintenance surface (Diagnostics / Checks / Updates, `Ctrl+8/9/0`); command palette groups results with pin actions and legacy v22 aliases.
- **Fluidity pass**: `backdrop-filter` dropped from five surfaces (status bar, dialogs, command palette, launcher dropdown), progressive environment recheck streaming, boot update scan deferred to idle and deduped, History rendered in batches of 60, MCP health pills fill in per-probe.
- **Accessibility & robustness**: missing-status chip fixed to WCAG AA (3.52:1 → 7.77:1 dark), MCP tolerant to malformed configs (per-CLI warnings instead of silent failures), CodeQL pointer guards in the Windows secrets path, Ko-fi support button in Help.

## Updater note

The fail-closed release pipeline introduced in v22.9.0 remains in force and is proven on this release: if `TAURI_SIGNING_PRIVATE_KEY` is not configured or the generated `.sig` is missing, the workflow aborts before publishing `latest.json`, and `scripts/audit-release.sh` re-checks that the published manifest carries a non-empty signature. An unsigned or empty-signature manifest cannot reach users, which protects the in-app updater from bricking itself with an update it would refuse to install.

## Notes

- All operations remain 100% local, offline-first, and private. No cloud sync, telemetry, or remote tracking.
- Windows remains the first-class platform; macOS and Linux builds ship the same core with platform-native secure storage and fail-closed gating for anything not yet available outside Windows.
- Race Mode requires the target project to be a git repository; races never execute inside the user's main checkout — every agent works in its own managed worktree under the app's races directory.
